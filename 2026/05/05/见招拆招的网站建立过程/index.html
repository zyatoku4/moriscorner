转为下载macports 安装两者 完成后在terminal输入

  • 01 更新 MacPorts
    先更新 MacPorts 的软件包索引，确保获取最新版本的 Git。
    在终端输入：
  • sudo port selfupdate
  • 等待更新完成
    02 搜索 Git 包
    确认 MacPorts 中可用的 Git 版本。
    在终端输入：
  • port search git
  • 你会看到多个相关包，例如 git、git-core 等
    03 安装 Git
    主要步骤
    安装 Git 主程序。
    在终端输入：
  • sudo port install git
  • 如果需要完整功能，可以安装 git-core
    04 验证安装
    确认 Git 已正确安装并可用。
    在终端输入：
  • git –version
  • 输出类似 git version 2.x.x 表示安装成功

分别输入git -v、node -v、npm -v，如果看到版本号，说明三者都安装成功，可以下一步

01 安装 Node 版本管理器 (nvm)
推荐方案
nvm 可以让你在用户目录下安装 Node.js 和 npm，避免权限错误。
在终端执行：

    03 重新安装 Hexo CLI
    在用户目录下安装 Hexo CLI，不会再遇到 EACCES 错误。
    在终端执行：
  • npm install -g hexo-cli
  • 安装完成后输入 hexo -v 验证是否成功

下一步：部署github pages
包含两步：确定自己的网址、开启github pages
用 GitHub Pages 的意思是：你把博客文件放到 GitHub（一个代码托管平台），它会帮你免费生成一个网站地址，这样别人就能访问你的博客了。
在 GitHub Pages 上，你的博客网址其实就是 仓库名和用户名决定的。
【遇到困难：没有仓库】

  1. 创建仓库
    登录 GitHub，点击右上角的 “+” → New repository”。
    在 Repository name 输入框里填名字：
  • 如果你想要网址是 https://你的用户名.github.io，仓库名必须写成 你的用户名.github.io。可能比较方便，但是会导致之后不可以更改网址。
  • 如果你写成其他名字，比如 blog，那网址就是 https://你的用户名.github.io/blog。以后可以多次更改网址。
    此处需要注意两种的区别！
    🟢 第一种：仓库名是 username.github.io
  • 网址固定：就是 https://username.github.io。
  • 如果你删掉仓库：这个网址就会失效，访问时显示 404。即使你在 _config.yml 里改了 url，也没用，因为 GitHub Pages 没有仓库来生成网站。
  • 解决办法：重新建一个同名仓库，再部署文件，网址就会恢复。
    🟡 第二种：仓库名是其他，比如 blog
  • 网址规则：https://username.github.io/blog。
  • 如果你改仓库名：比如把 blog 改成 notes，那网址就会变成： https://username.github.io/notes
  • 已有内容会不会丢？ 不会。仓库里的文件还在，只是网址路径变了。你需要在 _config.yml 里更新 url 字段，让 Hexo 生成的链接和新网址一致。
    📌 总结
  • 第一种（主页仓库）：删库 = 网址消失，必须重新建。
  • 第二种（子仓库）：改名 = 网址路径变，但内容还在，只要更新 _config.yml 就能继续访问。
    👉 所以区别在于：
  • 第一种网址更“固定”，删库就没了。
  • 第二种网址更“灵活”，改名后内容还在，只是路径不同。

选好哪一种，再进行命名。
命名后，选择 Public（公开），这样别人才能访问。

第二步：打开github pages
在myblog的_config.yml里找到如下部分，填写type、repo、branch（如选择第二种，就是写gh-pages）

此时输入用户名，然后需要回答token
这个token要到 GitHub → Settings → Developer settings → Personal access tokens 里生成一个。

  • 选择 repo 权限。
    在终端提示输入密码时，把这个 Token 粘贴进去。
    这样 Hexo 才能把文件推送到仓库。

每有一个编辑配置的行为，就写hexo clean && hexo generate && hexo deploy

【遇到问题：deploy后网站把源代码当成纯文本直接显示出来了】
npm install hexo-renderer-pug –save
npm install hexo-renderer-stylus –save
deploy，仍然不行
npm install hexo-renderer-pug –save –legacy-peer-deps
反复几次可以显示了，但是是纯http界面。反复检查了几遍上面的路径，最后发现是css引用路径错误。
进入主题文件夹-layout-partical-名字里有base的pug文件
找到引用 CSS 的那一行，通常长这样:
link(rel=’stylesheet’,href=’/style/index.css’)
把它修改为:
link(rel=’stylesheet’,href=url for(‘/style/index.css’))
按照指示找到了一行href=’/style/index.css’，把它改成了link(href=url_for(‘/style/index.css’), rel=’stylesheet’)
此时再次deploy，可以了。

下一步：换favicon
把要的图标文件放入博客的 themes/instapaper/source/images/ 文件夹内。

【遇到问题：没找到包含 favicon 或 favicon.ico 的行】
在主题的base.pug文件里没写favicon。手动添加。在title= currentTitle 的下方写：
link(rel=’icon’, href=url_for(‘/images/文件名’))

下一步：学发帖删帖
发帖在hexo的文档里有教，删帖就是找到那个md文件直接手动扔垃圾桶。
临时隐藏而非删除：如果你只是暂时不想让某篇文章显示，但以后可能还要发，不需要直接删除文件。你可以在文章顶部的配置（Front-matter）中添加一行 published: false。这样 Hexo 在生成网站时会自动跳过它。
Md文件顶部有几行被 — 包裹的内容，叫 Front-matter

  • 功能介绍：
    • tags (标签)：给文章贴标签，方便读者通过侧边栏点击标签查看同类内容。
    • categories (分类)：文章的归属，通常是层级化的（比如：学习 / 会计）。
    • sticky (置顶)：如果你想让这篇文章永远排在第一位，可以加一行 sticky: 1。
    • excerpt（摘要）：精准控制首页显示什么，和正文内容互相独立。
      在第二个 — 下方开始写你的内容。
      还有一些 Hexo 特有的功能：
  1. 设置首页摘要 (Read More)
    如果你不想让整篇长文章都堆在首页，可以在你想截断的地方输入：

（这是文章的开头介绍…）
!– more –
（这里是隐藏在“阅读更多”后面的详细内容。）

!– more – 之前的文字会作为首页预览，之后的文字只有点进文章标题才能看到。
2. 插入图片
将图片放入 source/images/ 文件夹，然后在文章中引用：
3. 引用与代码块
教别人知识时，这两个功能非常好用：

  • 引用：使用 > 标记重要结论。
  • 代码/公式：如果是会计分录，可以用代码块包裹，看起来更整齐。
    【遇到问题：写了<!– more —>，但没有显示预览】
    检查大半天，发现预览没出来，是因为第一句话写得太短了，触发了主题预设有的“垃圾过滤”机制。去掉主题的过滤机制后成功。

下一步，建立分类页
和about页类似，但是要在front-matter里加上：
type: “categories”
layout: “categories”

以上基本覆盖网页基础设置、主题基础设置，同理可以自定义大部分主题内容。随后改了每个页面留有的文字，建立了标签页。
建立友链页时，需要在根目录-source-links里index的front-matter里写：
links:

  • name: 名字
    url: 网址
    avatar: 头像
    desc: 签名
    这样算是添加了一个朋友。
    【遇到问题：友链没显示】
    在主题的layout文件夹里的links.pug文件里要求的属性名和我在index里写的对不上。
  • 你的 yml 里写的是 link:，但代码里要求的是 url:。
  • 你的 yml 里写的是 descr:，但代码里要求的是 desc:。
    两个需要一样。修改我的index。成功。
